# Decisions Log

> 用途：记录关键技术决策，重点写清楚“背景、选择、原因、影响”。

## 记录规则

- 只有在出现重要取舍时才新增，不需要为所有小改动都写一条
- 一条记录应回答下面几个问题：
  - 当时遇到了什么问题
  - 备选方案有哪些
  - 最终选了什么
  - 为什么这样选
  - 带来了什么收益和代价

## DEC-004 使用今日诗词 + 程序化背景替代旧阅读内容与远程图片路线

### 状态

- 已采纳

### 日期

- 2026-08-30

### 背景

- 当前产品目标从时间压力型海报转为低唤醒的书桌阅读摆件
- 目标设备仍是 `Raspberry Pi Zero 2 W`，内存和渲染预算有限
- 需要保留联网更新内容和离线回退，但不再希望远程图片成为稳定性和审美噪音来源
- 真机无代理实测表明：今日诗词读书接口可返回 `HTTP 200`；AIC 元数据接口可返回 `HTTP 200`，但 `www.artic.edu/iiif/2` 图片请求被 Cloudflare managed challenge 拦截并返回 `HTTP 403`

### 备选方案

- 保持旧的英文每日一句与远程图片路线
- 改为 AIC 元数据加远程 IIIF 图片路线
- 改为今日诗词文本内容加本地程序化背景

### 最终决策

- 阅读内容改为今日诗词五条白名单分类路由
- 背景改为程序化色板与抽象形状
- 缓存改为 `current` / `previous` 双槽 `daily-reading.json`
- 运行时不再请求、解码或缓存远程图片

### 原因

- 今日诗词接口返回内容小、响应稳定，更适合每天只拉一次的树莓派场景
- 程序化背景消除了远程图片的解码、裁切、缓存和可用性波动
- AIC 图片在目标真机环境里会被 `403` 拦截，不能作为主线路径
- 新设计更符合“轻触一下，先读一页”的产品方向

### 影响

- 文案、缓存结构、UI 布局和验证链路都转向每日阅读屏
- 磁盘不再被历史图片缓存持续占用；Slint 与系统字体的启动内存要用 `RSS + Swap` 同龄样本评估，不能只比较长期运行后的 RSS
- 文档、操作手册和架构说明必须同步改写

### 代价与注意事项

- 视觉多样性不再来自外部图片，而来自有限色板与版式变化
- 内容过滤只承担氛围保护，不等同于完整审查
- 2026-08-30 真机部署后，活动缓存为 `216B`，旧版约 `2.67MB` 图片缓存已精确清理；截图、点击与 DPMS 证据记录在迭代日志

## DEC-005 守护锁不得传递给时钟及辅助进程

### 状态

- 已采纳

### 日期

- 2026-08-30

### 背景

- 真机首次替换运行进程时，新 watcher 立即退出，但二进制单独运行正常
- `/proc` 与 `fuser` 证明旧版 watcher 的锁文件描述符被 `unclutter` 继承；watcher 停止后，辅助进程仍持续持锁

### 最终决策

- watcher 保留 FD 9 持锁，但调用 `run-clock.sh` 时使用 `9>&-`，不把锁传给子进程
- 部署脚本在迁移时定点结束旧 `unclutter`，释放历史版本已经泄漏的锁；随后 `run-clock.sh` 会重新启动它

### 影响

- watcher 生命周期重新成为锁的唯一所有者
- 重复部署可直接恢复，不再依赖手工删除锁文件；删除锁文件本身也不能替代释放持锁 FD

## DEC-002 旧版每日一句使用后台请求和单文件缓存

### 状态

- 已废弃（由 DEC-004 取代）

### 日期

- 2026-06-24

### 背景

- 旧版时钟需要展示每日一句与远程图片
- 目标设备内存有限，且断网不能影响时钟主功能

### 最终决策

- 使用后台线程执行 HTTPS 请求
- 本地只保留一份 JSON 和一张图片缓存
- 请求失败时继续使用上次成功缓存

### 原因

- 不阻塞 Slint 事件循环和每秒时钟刷新
- 避免引入数据库和复杂缓存管理
- 保证离线启动仍有内容可显示

### 代价与注意事项

- 首次从未联网时只能显示内置默认语录和纯色背景
- HTTPS 依赖会增加二进制体积和交叉编译时间

## DEC-003 使用 X11 DPMS 实现夜间息屏

### 状态

- 已采纳

### 日期

- 2026-06-24

### 最终决策

- 23:30–07:00 通过 `xset dpms force off` 息屏
- 触摸后通过 `xset dpms force on` 临时唤醒 60 秒

### 原因

- 复用当前 X11 运行环境，不引入硬件专属背光接口
- 与现有启动脚本中的 DPMS 配置保持一致

### 代价与注意事项

- 依赖 `DISPLAY`、`XAUTHORITY` 和 `xset`
- 不同触摸控制器在 DPMS 关闭后的事件传递行为需要真机验证

## DEC-001 从 `HTML + Chromium` 切换到 `Rust + Slint`

### 状态

- 已采纳

### 日期

- 2026-04-20

### 背景

- 目标设备是 `Raspberry Pi Zero 2 W`，只有 `512MB` 内存
- 原有 `HTML + Chromium` 方案实现快，但运行时成本较高，不利于长期稳定运行

### 备选方案

- 保持 `HTML + Chromium`
- 切换到其他原生 GUI 路线
- 切换到 `Rust + Slint`

### 最终决策

- 项目切换到 `Rust + Slint` 原生实现，并使用软件渲染方式运行

### 原因

- 降低内存占用
- 移除浏览器运行时依赖
- 减少首次运行弹窗和桌面浏览器副作用
- 更适合后续做开机直启和长期稳定运行

### 影响

- 代码结构从网页资源转为 Rust 源码 + Slint UI
- 运行方式从浏览器启动转为本地二进制启动
- 部署重心转移到 Rust 构建、交叉编译和树莓派运行脚本

### 代价与注意事项

- 团队需要维护 Rust / Slint 构建链路
- UI 调整需要重新编译，不像前端页面那样即改即看
- 后续每次 UI 或运行链路调整，都应同步维护文档资产
